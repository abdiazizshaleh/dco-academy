# Interface voice

Write as a knowledgeable colleague explaining the next step. The learner already works in IT support.

- Be specific: name the component, task, command, or result.
- Be direct: use short sentences and familiar verbs. Keep technical terms when they help.
- Be helpful: explain what the learner can do next when a check fails.
- Be natural: contractions are fine. Avoid motivational slogans, advertising copy, forced enthusiasm, and repeated three-part phrases.

Headings describe the task or content: "Server hardware", "Plan your study time", "Work the incident queue". Buttons name actions: "Explore the server", "Next lesson", "Verify recovery".

Keep implementation details in documentation. Explain a simulation limit in the interface only when it changes what someone should expect or do. Describe generated equipment images as illustrations; do not imply they are vendor service diagrams or real AWS facilities.

Technical lessons should teach the specific concept. Do not insert the same generic paragraph about safety, evidence, or confidence into every lesson. Put task-specific safety boundaries beside the relevant action.
